# ADR-001: физика закрытого сундука

Статус: выбранное решение для реализации; интеграционная проверка ещё не выполнена.

## Контекст

В старом приложении Physijs используется только в `ChestPhysicalScene.ts`: невидимый неподвижный пол и падающий закрытый сундук из convex meshes. Крышка является частью составного тела; код не использует шарниры. Открытие крышки и появление ключа — анимации GLB, не симуляция. Выбор приза и движение рулетки от физики независимы.

Нужно сохранить столкновения, отскок, наклон и скольжение. Поэтому временная анимация падения не является выбранной заменой.

## Выбор

Использовать `@dimforge/rapier3d-compat`, спрятанный за PhysicsWorldPort. Rapier даёт rigid bodies, friction/restitution, sleeping, CCD, простые и convex colliders. Официальная документация описывает асинхронную инициализацию, а compat-сборка включает WASM в JS. [Инициализация](https://rapier.rs/docs/user_guides/javascript/getting_started_js/), [коллайдеры](https://rapier.rs/docs/user_guides/javascript/colliders/).

Старый репозиторий `dimforge/rapier.js` архивирован из-за переноса bindings в основной репозиторий, что не означает прекращение разработки движка. Использовать [текущие TypeScript bindings](https://github.com/dimforge/rapier/tree/master/bindings/typescript), не старый репозиторий как показатель активности.

## Альтернативы

| Вариант | Оценка для этого проекта |
| --- | --- |
| Обновлять Physijs | Сохранит привычный API, но потребует сопровождать связку старого Three.js, geometry-конвертации, worker и Ammo. Для двух тел это неоправданная обязанность. |
| cannon-es | Простая JS-интеграция; не выбирается как долгосрочный ответ на устаревание. Документация Three.js отмечает отсутствие недавней поддержки. |
| Jolt | Актуальная альтернатива, но для этой сцены преимуществ перед Rapier не выявлено; отдельный движок и его API всё равно требуют адаптера. |
| Three.js RapierPhysics addon | Можно использовать для простых сцен, но прямой Rapier-адаптер позволяет явно управлять reset, остановкой, коллайдерами и временем. |
| Three.js анимация падения | Минимум зависимостей, но изменяет поведение: физические контакты заменяются заданной траекторией. |

Состояние перечисленных движков и способы интеграции: [официальный обзор Three.js](https://threejs.org/manual/pages/physics.html). Выбор — инженерная оценка применительно к коду этой репозитории, не универсальный рейтинг.

## Реализация адаптера

Один динамический rigid body для корпуса и закрытой крышки; один статический пол. Ключ скрыт при падении. Начать с двух box colliders на одном теле, размеры и offsets получить из геометрии корпуса/крышки в локальных координатах нормализованного корня. Если визуально неприемлемо — заменить коллайдеры на convex hull. Сохранять визуальные meshes и их материалы; не превращать mesh в объект физической библиотеки.

Нормализовать масштаб модели под метрическую сцену. Старые параметры: сундук `(0,312,0)`, поворот `(95°,0°,0°)`, масштаб `0.5`, пол `500×1×500` с центром `y=62`, гравитация `(10,-800,10)`, restitution сундука `0.3`, пола `1`, friction обоих `1`. Они являются эталонными настройками старой сцены, а не метрическими константами. Масштаб пересчитывается одной явной матрицей; параметры материала и combine rules калибруются отдельно, потому что одинаковые числа в разных движках не гарантируют одинакового отскока.

Физика вычисляется с шагом `1/60` секунды. Один browser frame-loop содержит accumulator; максимум пять substeps на кадр, большой dt ограничивается, после возврата из скрытой вкладки accumulator очищается. Между шагами допустима интерполяция poses. Один общий scheduler принадлежит композиции сцены, не use case и не домену.

Переход к открытию останавливает физику и переводит визуальную модель в авторскую позу opening-сцены. Для первого паритета сохраняется старое переключение сцены; плавное смешивание финальной физической позы и opening-позы — отдельное улучшение, не условие базовой реализации.

Reset удаляет старое тело и создаёт новое с нулевыми скоростями либо восстанавливает тело с полной очисткой velocities/forces. Dispose отменяет frame-loop, освобождает Rapier World (`free()`), Three.js ресурсы, listeners и ссылки. Материалы/геометрия, разделяемые моделями, освобождаются только владельцем asset-кэша. [World API](https://rapier.rs/javascript3d/classes/World.html).

Для столь маленькой сцены отдельный worker первоначально не нужен. Он добавляется только после измерений; новый worker-адаптер сохраняет тот же порт.

## Условия подтверждения выбора

Минимальная сцена должна собрать production bundle, загрузить WASM и Draco локально, показать корректные collider offsets и пройти 100 resets без роста числа тел, listeners и loop callbacks. Проверить холодную загрузку, скрытую вкладку, 30/60/120 Hz и resize. Это обязательная проверка реализации, а не уже полученный результат.

## Реализация в итерации 03

Добавлены RapierPhysicsWorld и ThreeChestDropScene. Координаты нормализуются до ширины закрытого сундука 1.7; стартовая высота центра 3.3, наклон 5°. Гравитация `(0.12,-9.81,0.12)`. Friction 1, restitution 0.3 для сундука и 1 для пола; combine rule явно Multiply. Это начальная калибровка, а не подтверждённое совпадение с Physijs.

Составное тело имеет два box colliders, рассчитанных из корпуса и крышки после применения исходных GLB matrixWorld. До следующего открытия key скрыт. CCD включён; reset создаёт новое тело с нулевыми скоростями внутри прежнего мира. Camera FOV 50°, position `(6,4,-6)`, look-at `(0,1.5,0)`. Все визуальные параметры требуют браузерной проверки.

Код готов к проверке, но ADR ещё не подтверждён интеграционно: npm registry недоступен, пакет Rapier отсутствует. Написаны три теста настоящего WASM (падение, 100 resets, отмена init); запуск сейчас останавливается на ERR_MODULE_NOT_FOUND. Подробности: [итерация 03](./iteration-03.md).
