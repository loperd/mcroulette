# Поведение MC Roulette

## 1. Сохранение логики и исправление дефектов

«Паритет» означает сохранение пользовательского сценария, внешнего вида и правил выбора целевого предмета. Гонки, утечки и выходы за границы массива не являются обязательным поведением. Ниже существующая логика и принятые изменения разделены явно. Визуальные параметры основаны на коде; точный вид требует запуска эталона.

## 2. Данные

Item: `id: string`, `title: string`, `image: string`, `rarity: 'default' | 'primary' | 'legendary'`, `displayWeight: number`. Старые `type` и `chance` преобразуются адаптером в rarity/displayWeight. JSON содержит числовые id и строковые chance; адаптер приводит типы, проверяет конечные неотрицательные веса, уникальность id, известную редкость и непустые title/image. Относительные URL разрешаются с учётом deployment base path.

В текущем каталоге 14 предметов, сумма chance = 100. Каталог запрашивается один раз и кэшируется; старый код допускает два одновременных запроса из разных компонентов — новая версия объединяет их в один in-flight promise. `selected_prize.json` содержит King, id `14`. Его результат запрашивается на каждое открытие и считается авторитетным.

`chance` управляет частотой изображения предмета в ленте, не фактической вероятностью выигрыша. Будущий server adapter не должен вычислять результат на клиенте.

## 3. Загрузка и начальный экран

Отображаются фон Minecraft, декоративные круги, loader с прогрессом. Загружаются каталог, модель, Draco decoder, физический движок и звук. Модель — `public/models/treasure-game.glb`, 214 780 байт, Draco. Вторая GLB в `src/assets/models` имеет другой размер и клип ключа; эталоном служит public-копия.

Сцена содержит `Chest_bottom`, `Chest_top`, `Key`. Клипы — `Chest_topAction` и `Key.001Action.001`. Узлы и клипы ищутся по именам через asset manifest; обязательные элементы проверяются при загрузке. Порядок children/animations больше не является контрактом.

В старом loader финальный progress запускает скрытие контейнера через 800/1400 ms, loader через 1600/2400 ms и событие готовности через 2400 ms. В новой версии прогресс декоративный: готовность определяется завершением обязательных ресурсов. Звук необязателен; его ошибка не блокирует запуск. Переход loader сохраняет характер исходной анимации, но не искусственное ожидание каждого таймера.

После загрузки сундук падает на невидимый пол. Показываются каталог с картинками, названиями и цветами редкости, Open Chest и Close. Старый Close в каталоге не имеет обработчика; новая версия оставляет его скрытым до появления реального требования, а не придумывает навигацию. Это намеренное изменение интерфейса.

Open доступен после обязательной загрузки; ожидание полного успокоения тела не требуется, поскольку старый код его не проверяет. Повторное нажатие во время открытия/вращения игнорируется.

## 4. Открытие

Open создаёт один sessionId, блокирует новое открытие и скрывает каталог через fadeOutDown. Подготовка выигрышного предмета/ленты и анимация сундука могут идти параллельно. Вращение начинается только после успешного завершения обеих операций.

Сундук переключается с физической сцены на opening-сцену: исходная поза `(x=-5.1570,y=63.1231,z=-5.6635)`, rotation приблизительно `(π/2,0.0000823,-0.03369)`, scale `0.5`. Авторская камера `(600,150,-250)`, perspective FOV 50°, near 0.1/far 1000. После нормализации единиц положения камеры и модели пересчитываются совместно.

`ScaleMove` в старом коде снижает y на 10, увеличивает z на 0.1 и scale на 0.0205 за кадр, до приближения на 10 единиц к y−260. Это приблизительно 25 кадров перемещения при обычных условиях, около 0.42 s на 60 Hz. Новая версия использует elapsed time и настроенные конечные transforms; длительность калибруется по эталону, а не зависит от Hz.

Затем ключ становится видимым, одновременно проигрываются два клипа один раз с фиксацией финального кадра. Сигнал завершения выдаётся по фактическому окончанию самого длинного обязательного клипа. Старый `sum(duration) * 500` заменяется явным условием.

После окончания анимаций сундук скрывается. Вращение ждёт готовую ленту. При ошибке prize-запроса нет вращения и выдачи фиктивного выигрыша: интерфейс показывает ошибку и позволяет повторить подготовку того же открытия либо вернуться к начальному экрану. Поздние результаты отменённой сессии игнорируются.

## 5. Лента и выбор позиции

Существующий алгоритм:

1. Каталог перемешивается.
2. Для каждого предмета вычисляется `round(40 * chance / 100)` копий; число копий ограничивается оставшимся местом до 40.
3. С полученными весами получается 39 элементов, а не 40. Старая переменная `totalCountPrizes=40` — верхняя граница, не гарантированная длина.
4. Выбранный приз ищется по id. Из совпадающих позиций выбирается одна случайная. Если совпадений нет, приз вставляется в ленту.
5. Старая позиция для rotateTo — 1-based; новый внутренний контракт строго 0-based.

Для первого переписывания сохраняется правило округления и ограничение 40. Не заменять его автоматически нормализованным распределением на ровно 40: это отдельное продуктовое изменение. В demo King получает ноль копий при округлении, затем добавляется при выборе выигрыша; получается 40 элементов.

Изменения: случайная позиция совпадения принадлежит `[0, matches.length)`; вставка при отсутствии принадлежит `[0, strip.length]`. Итоговая длина и целевой индекс вычисляются после вставки. Новая версия вставляет предмет в допустимый массив, а не в диапазон nominalCount независимо от реальной длины. Пустой исходный каталог — ошибка загрузки; полностью нулевые displayWeight допустимы и дают ленту из единственного выбранного предмета. Целевой индекс всегда валиден. Изображённый под курсором предмет всегда совпадает с авторитетным результатом.

Старая лента создаётся один раз при mounted и повторно используется после закрытия выигрыша; вставленные ранее призы остаются в ней. Новая версия также хранит session strip между открытиями. Полная перезагрузка каталога/новый запуск пересоздают её.

Случайный offset остановки принадлежит центральным 80% карточки: от −0.4 до +0.4 её ширины относительно центра. Случайность положения и состава ленты не изменяет выигрыш.

## 6. Вращение и звук

Две синхронные копии ленты: фон с blur и центральная увеличенная область, фиксированный курсор в центре. Исходные размеры: карточка 150 px, высота ленты 100 px, gap 5 px, zoom 1.2; центральная маска `circle(15% at 50% 50%)`. Цвета: default синий, primary фиолетовый, legendary красный.

Старый rotateTo вызывается с `time=5`, random=true, acceleration=500, duration=1200. Это не пять кругов и не гарантированно пять секунд. Код вычисляет `v0 = acceleration * time`, предварительную дистанцию `v0²/(2*acceleration)`, затем округляет число полных оборотов вверх по длине ленты и добавляет расстояние до цели. Фактическое время зависит от конечной дистанции и множителя duration.

Базовая кинематика сохраняется: при расстоянии D, ускорении торможения a, `v0=sqrt(2*a*D)`, `T=v0/a`, `s(t)=v0*t-a*t²/2`. Для старого множителя времени `t = elapsedMs/1200`. В новой конфигурации это называется `timeScale=1.2`, а не duration; elapsedSeconds делится на timeScale. Дистанция рассчитывается из текущего offset, целевого индекса, целевого jitter и числа полных оборотов, чтобы гарантировать пересечение целевой карточки курсором.

Позиция ленты задаётся абсолютным offset из elapsed time. Пропущенные кадры не теряют перемещение; recycling/виртуализация остаются внутренними деталями renderer. Изменение viewport во время вращения сохраняет логическую позицию и цель, пересчитывает screen offset. Размеры карточек фиксированы базовой темой; responsive-изменение ширины требует сохранения позиции в единицах карточки.

При пересечении границы карточки проигрывается click.wav с volume 0.05. Старый код клонирует Audio; новая версия использует ограниченный audio pool либо Web Audio, подавляет audio errors и ограничивает частоту звуков после пропущенного кадра. Звук разблокируется пользовательским Open. Запрет autoplay не прерывает сценарий.

## 7. Остановка и повторный цикл

В конце offset фиксируется точно на рассчитанной цели. Старый stop публикует ROULETTE_STOPPED через 1200 ms, затем лента начинает скрываться; её DOM очищается через 200 ms. WinScreen появляется ещё через 600 ms. Для паритета эти задержки хранятся в presentation config как holdAfterStop=1200 ms и revealAfterHide=600 ms, а не распределяются по компонентам.

Окно выигрыша показывает title, image и rarity выбранного Item; не извлекает результат заново из DOM. Close Win скрывает окно, сбрасывает сундук и снова запускает падение; каталог возвращается через 500 ms. Структура ленты сохраняется, её положение сбрасывается для следующего вращения.

Каждое открытие вызывает ровно один запрос результата. Повторный Close во время reset игнорируется. Dispose/навигация отменяют сценарий и освобождают ресурсы. Скрытая вкладка приостанавливает визуальное время; после возврата нет скачка физики и пачки звуков.

## 8. Приёмка

| Сценарий | Проверяемый результат |
| --- | --- |
| Холодная загрузка | Есть прогресс; Open появляется только при готовности обязательных ресурсов; сундук падает, каталог показывает 14 предметов. |
| Демо-открытие | Один запрос selected_prize.json; открытие крышки и ключа; обе ленты совпадают; под курсором King; окно показывает King. |
| Приз присутствует/отсутствует | Валидный 0-based targetIndex; выбранный id под курсором; вставка не теряет существующие карточки. |
| Много совпадений | Seeded random никогда не выбирает индекс вне массива. |
| Задержка JSON | Крышка может открыться раньше ответа; вращение ждёт ответ; повторный Open ничего не запускает. |
| Ошибка JSON | Нет фиктивного выигрыша; есть retry/reset; поздний ответ предыдущей сессии не влияет на новую. |
| Ошибка модели/WASM | Понятная ошибка и возможность перезапуска; нет бесконечного loader. |
| Ошибка звука | Полный цикл работает без звука. |
| Нулевые веса / пустой каталог | Один target slot для нулевых весов; пустой каталог отклоняется; выбранный приз имеет валидные данные. |
| Resize и 30/60/120 Hz | Цель не меняется; длительность opening не зависит от FPS; нет резкого пробивания пола. |
| 100 повторов | Один scheduler, постоянное число тел/обработчиков; очистка DOM и GPU/WASM при dispose. |
| Повторный запуск приложения | Состояние сброшено, assets могут быть закэшированы; новая композиция не наследует старые подписки. |
| Production deployment | Модель, иконки, Draco и WASM доступны локально, включая deployment в подкаталоге. |

Нужно записать эталон старой версии: загрузка, падение, Open, stop, win, Close; viewport 1440×900 и мобильный. До получения эталона численные допуски для камеры/траекторий остаются непроверенными. Приёмка логики проверяется независимо от визуального сравнения.
