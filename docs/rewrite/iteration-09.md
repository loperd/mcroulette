# Итерация 09: исправление подготовки сундука и собственный дизайн

Пользователь уточнил: восстанавливается внешний вид и поведение собственного старого CSS/JS, а не буквальная копия CS:GO и не прежний технический стек.

Ошибка подготовки воспроизведена настоящими Rapier-тестами: WebAssembly.instantiate выдавал CompileError. Установленный node_modules/@dimforge/rapier3d-compat/dist/rapier.mjs содержал 414 820 нулевых байтов внутри base64 WASM. Отдельный WASM-файл проходил WebAssembly.validate. Причина появления повреждённых байтов не установлена.

Архив пакета 0.21.0 из npm cache проверен SHA-512 против integrity из package-lock.json: совпадение. В этом архиве JS целый, без нулевых байтов. Пакет переизвлечён из проверенного архива без изменений в коде зависимости или её версии. Дополнительная проверка 2334 установленных JS/MJS/CJS/JSON-файлов не обнаружила других нулевых байтов. Vite dependency cache удалён, изменение mtime vite.config.ts запрашивает перезапуск dev-сервера; после обновления страницы оптимизатор должен использовать исправленный пакет.

После исправления npm run test:all проходит: 82 базовых, 25 UI/Canvas, 3 настоящих Rapier-теста. Проверено падение compound body, sleeping, 100 resets, постоянное число тел/коллайдеров и отмена init. npm run build проходит вместе с полной типизацией настоящих Three.js/Rapier API и синхронизацией Draco. Build сообщает о крупном JS chunk около 5.24 MB; оптимизация загрузки остаётся отдельной задачей.

В оформлении IntroScene использованы собственные ChestInsides.vue/main.styl: светлый радиальный фон предметов, вертикальные цветные полосы редкости, подписи с тенью, зелёная градиентная кнопка с исходными цветами/радиусом. Убрано тяжёлое затемнение Minecraft-фона. Реализация остаётся React/CSS с существующими независимыми сценами; Vue/Stylus/animate.css не возвращаются. Это восстановление основных визуальных признаков, не заявление о точном совпадении скриншотов.

Проверка страницы через Arc MCP заблокирована требованием approval при политике never; подключение из shell к пользовательскому localhost также недоступно. Поэтому GLB/Draco и весь сценарий с реальной отрисовкой в браузере пока не просмотрены. Следующий шаг — обновить http://localhost:5173/ и проверить Open: разъезд → падение → открытие → вспышка → рулетка. Если ошибка остаётся, нужна её новая причина из консоли; прежний WASM CompileError устранён в установленном пакете и интеграционных тестах.
