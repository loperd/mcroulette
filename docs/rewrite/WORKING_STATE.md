Обновлено 2026-10-16. Этот файл — состояние работы; не заменять цель последним коротким комментарием пользователя.

## Согласовано

- Продукт называется Voxel Vault и продаётся владельцам Minecraft-серверов.
- Игрок находит/покупает экземпляры кейсов. Главный рабочий экран — **инвентарь игрока**, из него открывается выбранный принадлежащий игроку экземпляр. Каталог типов/коллекций — отдельный раздел, не замена инвентарю.
- Существующий экран Ender-кейса — страница конкретного сундука. Его композиция пользователю нравится и зафиксирована. Не менять масштаб, расположение, тексты/панели самовольно.
- Выбран атмосферный Ender. Альтернативные визуальные направления оставлены для сравнения.
- Исходная зелёная кнопка сочная, но чужая по цвету. Плоская тёмно-бирюзовая не понравилась. Текущая итерация сохраняет объём, насыщенный градиент и свечение, используя бирюзово-изумрудную палитру.
- Новый пробный экран каталога **не принят**: пустой, простой, нет игрового характера, слабые карточки и композиция. Не объявлять его готовым главным экраном.
- Каждый экземпляр кейса проживает длительный жизненный цикл. У него свои метаданные: модель/вариант, seed, палитра/цвет отдельных частей, трещины, износ, другие изменения. Это сохраняемое состояние экземпляра, а не только кратковременные эффекты анимации.
- На всех страницах внешний вид должен строиться из актуальной модели + метадаты экземпляра. Статичный постер базового Ender не заменяет эту систему. Общая сборка модели для сцены и превью, ограниченное число WebGL-контекстов, кеш превью по revision модели и метадаты, инвалидация при изменениях.
- Текущую Ender-модель нужно существенно улучшить в Blender: привлекательный собственный вид, лишь отдалённо напоминающий Minecraft Ender Chest. После неё — ещё **две отличающиеся модели**, а не перекраски того же сундука.
- Маршрутизатор и запоминание состояния нужны всем экранам; прогресс и награда активной сессии должны восстанавливаться без повторного розыгрыша.
- Пользователь разрешил коммитить. `git add -A` 2026-10-16 отклонён файловой песочницей: `.git/index.lock: Operation not permitted`. Коммит не создан; не утверждать обратное.

## Что реализовано в текущем рабочем дереве

- Полный цикл Ender, эффекты, трещины со следом, Canvas-рулетка, награда, истории 14 предметов, осмотр с навигацией, звук с сохранением выбора, последняя находка по caseId.
- Последняя находка проверена интеграционным тестом реального цикла: появляется только после показа награды, сохраняется, доступна для осмотра.
- Реестр определений кейсов: model path, узлы/клипы, источники каталога/приза, тексты коллекции.
- Hash-router: каталог, кейс, предмет, открытие и награда; отдельные версии снимков браузерного состояния; scoped session journal.
- Восстановление открытия: тот же sessionId и уже выбранная награда; рулетка повторяет сохранённый план, физическая часть повторяется с начала фазы. Это не восстановление точного физического кадра.
- Пробный каталог и базовый Blender-постер существуют как черновик. Реальный инвентарь ещё не реализован. Контракт внешности, зоны окраски и применение сохранённых повреждений уже добавлены; запись новых повреждений в lifecycle экземпляра ещё не подключена.

## Нельзя потерять при следующей итерации

Не моделировать владение одним только типом кейса. Нужен отдельный instanceId и защита от повторного открытия экземпляра. Сохранение визуальных настроек в браузере не делает браузер источником прав на кейсы/призы. При интеграции сервер определяет владение, результат и выдачу, с идемпотентностью по sessionId.

Проверки записывать по факту; сборка не подтверждает визуальное качество. Не добавлять новые декоративные слои без связи с этапом сцены. Не прыгать от каталога к последней находке, затем к модели без завершения выбранного блока.

## Исправление действия при осмотре использованного экземпляра

Причина: CTA проверял только status экземпляра в URL. При opened выводилось «Вернуться в инвентарь», даже когда счётчик показывал другие доступные экземпляры того же типа. Теперь caseOpenAction выбирает доступное действие из всего инвентаря: выбранный неиспользованный экземпляр приоритетен, затем доступный того же типа, затем незавершённый. При осмотре использованного и наличии другого доступного кнопка «Открыть следующий сундук» переключает instanceId и после инициализации сразу начинает его открытие одним нажатием. Намерение открытия кратковременное, отменяется уходом с маршрута; права/claim остаются в контроллере. Изменения инвентаря обновляют счётчик и CTA. Если доступных/незавершённых нет — возврат в инвентарь. Три регрессионных теста проверяют подбор, сохранение выбранного, запрет повторного открытия и продолжение незавершённого.

## Группы вместо сотни карточек и общие показатели

Инвентарь группируется по типу, всем четырём цветам, уровням повреждений отдельно корпуса/крышки, статусу, награде открытого экземпляра. Уникальные id/seed и метадата сохраняются, превью/переход соответствуют первому экземпляру группы. Износ разбит на 0 / до 25 / до 50 / до 75 / до 100%; группа показывает диапазоны, осмотр — точные проценты. Количество, износ, палитра и статус видны на карточке/экране сундука, доступное количество — в каталоге и награде. Детали: inventory-grouping.md. Проверены 8 профильных тестов и UI-набор, production build проходит; визуальную оценку игрового браузера не заявлять.
