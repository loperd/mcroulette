# Маршруты и восстановление

## Текущие маршруты

Hash-адреса работают без серверного rewrite и сохраняют deployment prefix и query-параметры вариантов оформления.

- `#/cases` — черновой каталог типов кейсов; визуал не принят пользователем.
- `#/cases/ender` — существующий принятый экран Ender.
- `#/cases/ender/items/14` — осмотр предмета с историей.
- `#/cases/ender/opening/<sessionId>` — активное открытие.
- `#/cases/ender/reward/<sessionId>` — результат.

Первый вход пока ведёт на Ender, до появления полноценного инвентаря. Повторный вход без hash восстанавливает последний адрес. Явная ссылка имеет приоритет. У неизвестного кейса — отдельный экран ошибки; неизвестный предмет не подменяется другим. Покупка и владение не выводятся из URL.

## Что сохраняется

BrowserRouter хранит последний маршрут. Осмотр выбранного предмета — часть адреса. Прокрутка содержимого сохраняется по caseId. Черновой каталог сохраняет поиск, коллекцию и прокрутку. Звук и последняя находка сохраняются независимо.

SessionJournal — порт application, браузерный адаптер использует версионированные snapshots. Контроллер сохраняет sessionId до запроса результата, выбранный приз сразу после ответа и strip/SpinPlan до показа рулетки. При восстановлении:

- незавершённая физическая часть повторяется с начала фазы с тем же sessionId и уже выбранным призом;
- рулетка повторяет тот же сохранённый план и выбранный приз;
- показанная награда открывается сразу, без нового выбора и прокрутки;
- Close очищает checkpoint до возврата к превью;
- уход с экрана освобождает Three/Rapier/Canvas/audio, не удаляя checkpoint.

Это восстановление смыслового состояния, а не точного кадра GPU/физики. Snapshot браузера не даёт прав на награду. При подключении backend требуется восстановление/проверка серверной сессии и идемпотентность выдачи. Пока результат приходит из существующей fixture-службы.

## Следующее расширение

Инвентарь должен хранить **экземпляры** с instanceId, lifecycle и метаданными внешности. Ключи сессий и экранов владения будут scoped по instanceId, а не только caseId. Тип кейса описывает модель/контент; экземпляр описывает собственность и индивидуальные изменения. Главным экраном станет инвентарь, каталог останется отдельным разделом.

Превью экземпляров нельзя строить из общего статичного постера: общая сборка модели + актуальная метадата, ограниченное число WebGL-контекстов, кеш по revision модели/экземпляра. Сейчас Blender-постер — только временный ресурс чернового каталога.

## Проверки

Проверены перезагрузка на физической фазе, незавершённый запрос с тем же sessionId, восстановление точного SpinPlan, восстановление награды и очистка после Close, изоляция журналов кейсов, повреждённые/будущие snapshots и недоступное хранилище. UI-тесты проверяют прямой URL предмета, перелистывание с изменением адреса, закрытие навигацией и восстановление последнего маршрута. Production build проходит. Ручной визуальный просмотр браузера агенту недоступен в текущем окружении.
